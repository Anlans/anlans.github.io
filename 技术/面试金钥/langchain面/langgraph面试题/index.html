    langgraph面试题准备¶

    1. langgraph核心概念¶

    1.1 为什么langchain要引入langgraph以图形式作为核心架构？（而不是传统的chain）¶

    详细解答

    因为实际需求中任务一般不是线性的，需要分支、判断、循环等复杂流程。而langgraph用图来建模每个节点之间的控制流，更加灵活，天然支持agentic workflows，拥有决策路径选择能力。

    1.2 什么是多智能体系统¶

    详细解答

    多智能体系统指多个AI角色（agents）协同完成任务，如一个planner、一个researcher，一个reporter。

    1.3 LangGraph 的“时间旅行（Time Travel）”功能是怎么实现的？为什么它强大？¶

    详细解答

    time-travel-in-langgraph文档 它基于持久化的StateSnapShot(状态快照)，允许从任意历史节点恢复状态并“分叉”出一个新的执行路径。方便回溯错误、测试不同策略，支持构建多结局应用，如交互式小说、AI辩论助手等。

    1.4 什么是langgraph的持久层(Persistence Layer)？为什么这是其核心能力？¶

    详细解答

    持久化层记录每一次图执行过程的状态（消息、变量、位置等），实现memory、人类反馈、时间旅行等提供基础技术。可选内存、SQLite、PG、Mongo等数据库进行持久化，非常适合构建可恢复、可审计、具备容错能力的AI应用。

    1.5 langgraph怎么定义和处理memory？与传统RAG记忆机制有何不同？¶

    详细解答

    langgraph的memory是任意结构化状态的保存与恢复，并不知识聊天历史记录。

    传统RAG记忆就是拼接历史记录，而langgraph内置的状态快照或者说checkpoint能够让每一步决策都有其上下文，从而可以实现更精细可控的记忆能力，非常适合多轮任务型智能体。

    1.6 LangGraph 提供的“Streaming”输出机制为什么对用户体验很重要？¶

    详细解答

    Streaming 功能让你在模型还未完全生成响应前，就可以逐步显示中间结果。这大大提升了交互实时性。

    1.7 LangGraph 的 Pregel Runtime 是做什么的？¶

    详细解答

    Pregel 是 LangGraph 的运行时系统（runtime system），负责调度节点、管理状态更新、记录 checkpoint 等。

    1.8 langgraph的节点如何工作？¶

    详细解答

    每个节点就是一个python函数，它接受当前State，然后处理返回一个增量更新的State（如增加一条AI回复）。

    1.9 不用内存作为持久化方式，用什么存储Checkpoint？¶

    详细解答

    除了内存（MemorySaver），LangGraph 还支持 SqliteSaver、PostgresSaver，你也可以自定义持久化逻辑（如接入 Redis、MongoDB、Cloud Storage 等）。这意味着你可以把对话状态永久存储，实现真正的“长记性”智能体，或跨设备、跨平台继续会话。
