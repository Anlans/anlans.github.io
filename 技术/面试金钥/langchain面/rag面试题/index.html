    rag面试题准备¶

    1. rag基础面¶

    基础过一遍就行

    1.1 为什么需要外挂向量库（或者es库）知识库？¶

    详细解答
    1. 持久化记忆
    2. 降低模型环境，提升回答准确率、权威性和时效性
    3. 解决通用模型对小众领域没有涉及到的问题
    4. 提高模型的安全性和可靠性 相比fine-tunning成本较低,效果b

    1.2 RAG思路什么样的？¶

    详细解答

    加载文件➡️读取文件➡️

    文本分割➡️文本向量化➡️

    问句向量化➡️在文本向量中匹配与问句最相似的topk➡️

    选中的topk个文本与上下文一起塞给Prompt后再给LLM➡️提交给LLM生成回答

    1.3 RAG的核心是什么？¶

    详细解答

    RAG的核心是Context，即上下文，与之同样重要的就是embedding了，把知识库内容经过embedding嵌入向量知识库中

    1.4 RAG的Prompt模版构建？¶

    详细解答 
    你是某某某公司的智能客服助手，你的名字是xx，
使用以下上下文(由<ctx></ctx>标记)和聊天历史(由<hs></hs>标记)来回答用户的问题:

</ctx>

{history}

请根据以上规则,认真思考后回答用户问题。

    1.5 如何评价RAG项目效果好坏？¶

    详细解答

    分两个环节进行评估：

    1) 检索环节

    • MMR (平均倒排率): 用于评估推荐系统排序性能的指标，计算方式是取用户的每个查询的排名倒数的平均值。越靠前影响越大。
    • Hits Rate (命中率): 查询的准确率，前k项中，包含正确信息的项的数量占比

    2) 生成环节

    1.6 通用RAG的改进点？¶

    详细解答
    • query侧，对query进行扩写举一反三（如知识库中有英文内容如论文，则应扩写成英文）同时进行查询，这在langchain中的实现是MultiQueryRetriever和HydeRetriever，前者生成多个查询变体，后者生成假设文档来增强检索。
    • 速度侧，对向量库做层次索引，提高检索效率
    • 微调侧，由于一般检索过程中使用都是通用型模型，并且体积较小在M范围内。所以针对当前垂直领域引入知识库
    • 输出侧，对最终数据进行处理

    当然最好还是加入多路召回，如向量搜索+全文搜索二路归并。同时还有其它召回方法，可能会引入更多其它的模型。

    1.7 文档切割方式？¶

    详细解答

    最好的方式是按照语义分割，因为如果简单的按照标点符号分割，可能导致检索出来的文本就是不全的，所以会使模型回答的点不完整。如果切割粒度太大，好多段落一分，会因为召回片段太大，那么就会导致噪声变大，模型本就有幻觉，这样会使得模型摸不着头脑导致回答不准。

    1.8 如何进行语义切割？¶

    详细解答

    语义切割是按照文档其意义和上下文分割成较小块的方法，而不是基于固定的长度或分隔符。确保每个块都都包含完整的语义信息，对RAG的检索和生成阶段特别重要。

    说一下两种方法：

    1. langchain中的SemanticChunker工具，根据连续句子的相似性进行分割。可参考langchain 

      from langchain_experimental.text_splitter import SemanticChunker

chunker = SemanticChunker()
document = "长文档文本..."
chunks = chunker.split_text(document)

    2. 使用NLP库如spaCy识别语义边界 

      import spacy

nlp = spacy.load("en_core_web_sm")
document = "长文档文本..."
doc = nlp(document)
chunks = [sent.text for sent in doc.sents]

    1.9 请描述使用langchain构建一个文档问答系统的关键技术组件及实现¶

    详细解答

    两个核心阶段：

    1) Indexing（文档索引阶段）

    数据准备过程包含三个步骤：

    • 文档加载：使用Document Loader加载各种格式的文档
    • 文档分块：使用Text Splitter将文档切成小块
    • 向量化存储：为上述文本块创建向量嵌入（embeddings）并存储到向量数据库中

    2) Retireval & Generation（问答检索&生成阶段）

    问答检索&生成阶段包含两个步骤：

    • 检索：使用RetrievalQAChain从向量数据库中检索与用户问题最相关的topk文本块
    • 生成回答：将检索到的文本块与用户问题一起输入到LLM中，生成最终的答案

    1.10 什么是向量数据库？在大模型应用开发中，向量数据库主要解决什么问题？¶

    详细解答

    1) 主要解决：

    • 高效存储和检索外部知识、
    • 解决上下文长度限制、
    • 实现语义搜索和相关性匹配、
    • 提升推理效率和可扩展性

      直接在模型内处理大规模数据会导致计算成本高且推理速度慢，在企业级应用中，向量数据库可以处理数百万文档的嵌入，支持实时查询而无需每次都调用模型重新计算。

    1.11 向量数据库的索引算法？¶

    详细解答

    快速搜索算法有3️⃣种类型的算法：

    1. 基于图

      • 基于图的算法创建数据的图，其中每个数据点是一个节点，边表示数据点之间的接近性和相似性。如HNSW

    2. 基于hash

      • 基于hash的算法使用哈希函数将数据点映射到哈希码或桶。如MIH(多索引哈希)、LSH位置敏感哈希。

    3. 基于树

      • 基于树的算法将数据集划分为树状结构，以快速搜索。如kd树、RP树(随机投影树)。低维空间<10，基于树算法性能很有效。

    参考

    1）HNSW(Hierarchical Navigable Small World，层次导航小世界图)

    2）IVF（Inverted File Index，倒排文件索引）

    3）PQ（Product Quantization，乘积量化）

    4）FLAT（暴力搜索）：不构建索引，直接对所有向量进行逐一距离计算。准确无误差，大规模数据极慢

    1.12 向量嵌入模型和索引算法之间是什么关系？¶

    详细解答

    1) 可以概括为生产者与消费者：

    • 嵌入模型是上游，负责将原始数据转化为向量，是整个流程起点
    • 索引算法是下游，接收嵌入模型生成的向量以构建索引结构（如HNSW图）并支持快速查询

    1.13 重排序玩法？¶

    详细解答

    重排序是将检索到的文档重新排序，以提高相关性和准确性。

    1) 使用BM25在 rag 重排序步骤

    • 先用别的算法进行向量搜索出topk文档，但是topk可以大一些如100
    • 对这k篇文档跑一遍BM25，重新计算每个文档和query的相关分数
    • 根据BM25的重排序结果调整文档的顺序，挑出topn喂给LLM

    参考

    如何使用 

    # pip install rank_bm25
from langchain_community.retrievers import BM25Retriever


retriever = BM25Retriever.from_texts(["hello, mr.pig", "cat", "dog", "bird", "animal"], k=5)

result = retriever.invoke("")
print(result)
